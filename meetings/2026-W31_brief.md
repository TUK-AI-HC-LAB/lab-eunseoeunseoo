## 1. 서론

### 1.1 연구 배경과 중요성
- 이 연구 문제가 속한 큰 영역: MVTec-AD 기준 산업 이상탐지(Industrial Anomaly Detection, IAD).
- 왜 중요한가: 제조 공정에서 결함을 자동으로 탐지·위치추정하는 것은 품질관리 비용을 직접 줄인다. 최근 memory-bank 기반 방법(PatchCore)이 매우 높은 baseline 성능을 보이지만, 특정 실패 유형이 반복적으로 관찰된다.
- 최근 흐름: zero-/few-shot vision-language 접근(WinCLIP), diffusion 기반 전체 이미지 재구성 접근(DiAD)이 patch 비교 프레임워크의 대안으로 제시되고 있다.

### 1.2 기존 접근의 큰 계열과 한계
- 접근 A — Memory-bank/feature 비교(PatchCore[1]): 사전학습 feature의 patch 단위 nearest-neighbor 비교. mean I-AUROC 99.1%로 매우 강력하지만(`method1_patchcore/markdown/baseline_analysis.md`), grid(전역 패턴)와 transistor(부품 배치)에서 상대적으로 약함.
- 접근 B — Vision-language zero-/few-shot(WinCLIP[2]): CLIP 기반 텍스트-이미지 정합으로 학습 데이터 없이 탐지. pill에서 PatchCore 대비 -15.6%p(zero-shot), -11.5%p(1-shot)로 반박됨(`method2_winclip/markdown/winclip_zeroshot_analysis.md`).

### 1.3 우리가 집중하는 접근과 남은 문제
- 이번 주 집중 접근: 전체 이미지 재구성 기반 diffusion 방법(DiAD[3], Candidate C).
- 기존 대안보다 나은 이유: patch 단위 비교가 아니라 전체 이미지를 재구성하므로, 원칙적으로 global pattern과 spatial arrangement 정보를 함께 활용할 수 있다.
- 아직 해결되지 않은 challenge 1: 로컬 8GB GPU로는 논문 기준 학습량(1,000 epoch, batch 12)을 채울 수 없다 — evidence: `method3_diad/markdown/setup_notes.md` 7~9절 OOM/속도 분석.
- challenge 2: DiAD 논문 자체가 H3/H4가 요구하는 "global pattern/spatial arrangement 이상"을 별도로 정의·측정하지 않는다 — evidence: `method3_diad/markdown/diad_summary.md` "Candidate C 검증(H3/H4)과의 연결" 절. 즉 논문의 성공이 곧 H3/H4의 지지를 의미하지 않으며, 우리가 직접 category-wise로 재현·측정해야 한다.

### 1.4 원인 가설
- 현재 관찰한 limitation: PatchCore가 grid(패턴 반복성 위반)와 transistor(부품 배치 이상)에서 상대적으로 약함(`method1_patchcore/markdown/baseline_analysis.md`).
- 원인 가설 H3: PatchCore의 고정된 3×3 local aggregation은 global pattern-regularity 이상을 잡기에 불충분하다.
- 원인 가설 H4: PatchCore의 per-patch independent scoring은 spatial-arrangement 이상(최고 점수 패치가 실제 결함 위치가 아닐 수 있음)을 못 잡는다.
- H3가 맞다면 관찰되어야 하는 현상: 전체 이미지를 보는 재구성 기반 방법(DiAD)의 grid I-AUROC가 PatchCore보다 높아야 한다.
- H4가 맞다면 관찰되어야 하는 현상: DiAD의 transistor pixel-level AUROC가 PatchCore보다 높아야 한다.

### 1.5 이번 주 선택한 방향
- 이번 주 해결 후보: DiAD(Candidate C) 실제 재현·학습·평가.
- 다른 후보(Candidate A 연장 등)보다 이것을 선택한 이유: H3/H4 둘 다 diffusion 기반 재구성을 직접 지목한다(`method1_patchcore/markdown/baseline_analysis.md` 후보 매핑 표).
- 이 선택이 H3/H4를 어떻게 검증하는가: grid/transistor에서 category-wise AUROC를 직접 계산해 PatchCore 수치와 비교.

### 1.6 이번 주 기여 또는 검토 초점
- 이번 주 brief가 보여주려는 핵심 판단: **같은 미성숙한 체크포인트에서도 H4는 이미 지지되지만 H3는 그렇지 않다 — 이 비대칭이 두 가설의 성격 차이(부분적 pixel-level 국소화 vs 전역적 image-level 판별)를 시사한다.**
- 이 판단을 지지하는 evidence 위치: `method3_diad/markdown/h3_h4_evaluation.md`.

## 2. 사전 지식과 문제 정의

### 배경
- W27(PatchCore 재현)과 W28(WinCLIP 재현)에서 도출된 H2/H3/H4 가설을 이어받는다. H2는 W28에 반박됨.

### 기술 용어
- *I-AUROC (image-level AUROC)* [1]: 이미지 전체가 정상/이상인지 분류하는 성능. `eval_results_epoch7.csv`의 `max` 컬럼. 예: grid 0.588 = grid 카테고리 이미지 판별 성능.
- *P-AUROC (pixel-level AUROC)* [1]: 픽셀 단위로 이상 위치를 얼마나 정확히 잡는지. `eval_results_epoch7.csv`의 `pixel` 컬럼. 예: transistor 0.945.

### 표기법
| 표기법 | 설명 |
|---|---|
| `I-AUROC` | image-level AUROC, 0~1 스케일 |
| `P-AUROC` | pixel-level AUROC, 0~1 스케일 |

### 정의
정의 1. Global pattern-regularity 이상(H3 대상). 반복 패턴(grid의 실 짜임 등)이 국소적으로는 정상 patch와 구분이 안 되지만 전체적으로 규칙이 깨진 경우.

정의 2. Spatial-arrangement 이상(H4 대상). 개별 부품(transistor의 다리 등)은 정상처럼 보이나 배치·위치가 틀린 경우.

### 문제 정의
문제 1. Multi-class unsupervised anomaly detection. 정상 이미지만으로 학습된 모델이 주어졌을 때, 우리의 과제는 테스트 이미지가 정상/이상인지(image-level) 및 이상이 있다면 어느 픽셀인지(pixel-level)를 결정하는 것이다. 구체적으로 우리는 카테고리 레이블을 학습에 쓰지 않는 multi-class 단일 모델 제약 아래에서 anomaly score map을 추정한다. 목표는 PatchCore가 상대적으로 약한 카테고리(grid, transistor)에서 baseline보다 높은 I-AUROC/P-AUROC를 얻는 것이다.

## 3. 관련 연구

### 3.1 현재 문제를 푸는 큰 연구 흐름
- 흐름 1 — Memory-bank/feature 비교: PatchCore[1]가 대표. 핵심 아이디어는 사전학습 feature의 patch 단위 최근접 이웃 거리. 한계는 local aggregation 크기에 의한 global context 손실. 현재 문제와의 연결: H3/H4의 baseline.
- 흐름 2 — 전체 이미지 재구성(reconstruction): DiAD[3]가 대표. 핵심 아이디어는 diffusion denoising으로 정상 이미지를 재구성하고 원본과의 차이를 anomaly score로 사용. 한계는 카테고리 정보를 보존하며 재구성하는 것 자체가 어렵고(DiAD의 SG network가 이를 위한 장치), 학습 비용이 매우 크다. 현재 문제와의 연결: H3/H4의 직접적인 검증 대상.

### 3.2 현재 원인 가설에 대응하는 관련 연구
- H3 관련: DiAD[3]는 diffusion의 전역적 재구성 능력을 사용하지만, 논문 자체는 global pattern-regularity를 별도 정의·측정하지 않는다(`method3_diad/markdown/diad_summary.md`) — 간접적 지지만 제공, 우리가 직접 측정해야 하는 이유.
- H4 관련: 동일하게 DiAD[3]는 spatial-arrangement 이상을 명시적으로 다루지 않으나, cable처럼 구조적 배선 오류가 많은 카테고리에서 경쟁력 있는 수치(AUROC-seg 96.8)를 보고한다 — 우리 실험(transistor)과 방향이 맞다.

### 3.3 이번 주 해결 후보 요약
- 후보 C(DiAD, 선택): 관련 연구 근거 위 3.2. 가능성 — 논문이 전역 재구성 능력을 이미 입증. 실패 가능성 — 로컬 GPU 제약으로 논문 수준 학습이 불가능해 실제 성능 확인이 어려움. 판단: 선택(제약 인지 후 진행).

## 4. 선택한 방법 또는 절차
- 이번 주 선택한 후보: DiAD(공식 repo clone, commit `d281300`) 재현.
- 다른 후보보다 이것을 선택한 이유: 위 1.5/3.3 참고.
- 기존 연구와의 차이: 논문 저자 설정(batch 12, fp32 Adam, 1,000 epoch)을 그대로 못 쓰고 로컬 8GB GPU에 맞춰 축소.
- 구현/protocol 변경(요약, 세부는 `method3_diad/markdown/setup_notes.md`): 8-bit Adam(`bitsandbytes`)으로 optimizer state 압축, batch size 2 + precision 16 + accumulate_grad_batches 4, step 기준 체크포인트(매 50 step)로 중간 진행 보존, epoch 종료마다 `method3_diad/source/epoch_log.csv`에 자동 기록·commit.
- 이 선택이 H3/H4를 어떻게 검증하는가: epoch 7 체크포인트로 `test.py` 평가를 실행해 category-wise I-AUROC/P-AUROC를 PatchCore 수치와 직접 비교(5절).

## 6. 논의
- 지금 주장할 수 있는 것: DiAD가 (미성숙한 상태에서도) transistor pixel-level 국소화에서는 이미 PatchCore를 능가한다 — H4 지지.
- 아직 주장할 수 없는 것: grid image-level 판별에서 DiAD가 PatchCore를 능가하는지 — H3는 미결정.
- 이번 결과가 원인 가설에 대해 알려준 것: H3와 H4는 같은 "전역 재구성" 메커니즘에 기대지만, 학습 초반에 드러나는 속도가 다르다 — pixel-level 국소화(H4)가 image-level 전역 판별(H3)보다 먼저 개선되는 것으로 보인다.
- 남은 불확실성: grid I-AUROC가 학습을 더 진행하면 개선되는지, 아니면 구조적으로 정체되는지 아직 모름.
- 다음 검증: 학습을 계속 진행하며(현재 epoch 14+) 이후 시점에 동일 평가를 재실행해 grid I-AUROC 추이를 확인.

## 8. 이번 주 주요 질문 1개
- 질문: 로컬 8GB GPU에서는 논문의 1,000 epoch 완주가 불가능한데, H3(grid)를 "판단 가능"하다고 볼 수 있는 최소 기준을 어떻게 정해야 할까요?
- 내가 현재 판단한 답: grid I-AUROC가 PatchCore(0.977)를 넘어서면 지지, 여러 epoch에 걸쳐 정체(예: 전체 평균은 오르는데 grid만 안 오름)되면 반박에 가깝다고 잠정 판단하고 있습니다.
- 그 판단의 근거: H4가 이미 이 시점에 baseline을 넘었다는 것은 모델이 학습되고 있다는 증거이므로, grid가 계속 안 움직인다면 단순히 "덜 학습돼서"가 아니라 구조적 문제일 가능성을 시사한다고 봅니다.
- 왜 이 판단이 틀렸을 수 있는가: grid가 다른 카테고리보다 diffusion reconstruction이 원래 느리게 수렴하는 카테고리일 수도 있어서, "정체"와 "느린 수렴"을 몇 epoch 만에 구분하기 어려울 수 있습니다.
- 교수님이 판단해주면 다음 주 무엇이 바뀌는가: 재평가를 몇 epoch 간격으로 할지, 그리고 언제 H3에 대한 최종 결론(지지/반박/미결정 유지)을 내릴지가 정해집니다.
