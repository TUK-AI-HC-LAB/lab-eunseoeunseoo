## 1. 서론

### 1.1 연구 배경과 중요성
- 이 연구 문제가 속한 큰 영역은 무엇인가: MVTec-AD 기준 산업 이상탐지(Industrial Anomaly Detection, IAD).
- 왜 이 문제가 실제로 중요한가: 제조 공정 결함을 자동으로 탐지·위치추정하는 것은 품질관리 비용을 직접 줄인다.
- 최근 어떤 흐름이나 접근이 이 문제에서 중요해졌는가: memory-bank/embedding 비교(PatchCore) 계열이 매우 높은 평균 성능을 보이지만, grid(전역 패턴)·transistor(부품 배치)처럼 특정 실패 유형이 반복 관찰됨 — 이를 diffusion 기반 전체 이미지 재구성 접근(DiAD, GLAD)으로 보완하려는 흐름이 이어지고 있음.

### 1.2 기존 접근의 큰 계열과 한계
- 기존 접근 A: PatchCore(memory-bank/embedding 비교).
- 접근 A가 유용한 이유: 사전학습 feature의 patch 단위 최근접 이웃 비교만으로 mean I-AUROC 99.1% 달성(`method1_patchcore/markdown/baseline_analysis.md`).
- 접근 A의 한계: 고정된 3×3 local aggregation과 patch별 독립 스코어링 때문에 grid(전역 패턴 규칙)·transistor(부품 배치)에서 상대적으로 약함 — H3/H4의 출발점.
- 기존 접근 B: DiAD(diffusion 기반 전체 이미지 재구성, `method3_diad/`).
- 접근 B가 유용한 이유: 전체 이미지를 재구성하므로 원칙적으로 global pattern과 spatial arrangement 정보를 함께 활용 가능.
- 접근 B의 한계: 로컬 8GB GPU 재현 기준 grid/transistor 지표가 학습이 진행돼도(loss 감소) 함께 개선되지 않는 비단조적 패턴을 보임(`method3_diad/markdown/h3_h4_evaluation.md`) — H3/H4 최종 판단을 못 내린 채 미결정으로 남음.

### 1.3 우리가 집중하는 접근과 남은 문제
- 이번 연구가 집중하는 접근: GLAD(Yao et al., ECCV 2024) — DiAD와 같은 diffusion 재구성 계열이지만, 샘플별 adaptive denoising step(ADS)과 영역별 spatial-adaptive feature fusion(SAFF)으로 "모든 샘플·영역을 동일하게 처리"하는 DiAD류의 한계를 직접 겨냥함(`method4_glad/markdown/ECCV24_GLAD_Towards_Better_Reconstruction_with_Global_and_Local_Adaptive_Diffusion_Models_for_Unsupervised_Anomaly_Detection.md`).
- 이 접근이 기존 대안보다 나은 이유: DiAD가 고정된 denoising 절차를 모든 카테고리에 동일 적용하는 것과 달리, GLAD는 카테고리·샘플마다 난이도가 다르다는 것을 명시적으로 모델링 — grid처럼 이상 난이도가 카테고리마다 다른 경우 고정 절차가 최적이 아닐 수 있다는 우리 H3 관찰과 문제의식이 맞닿음.
- 그러나 아직 해결되지 않은 challenge 1: 로컬 8GB GPU 재현이 이번 주 대부분을 차지해, 아직 category-wise 평가를 한 번도 실행하지 못함.
- challenge 1이 실제 문제인 evidence: `method4_glad/markdown/setup_notes.md`에 기록된 다수의 환경/코드 버그(의존성 비호환, Windows 경로 문제, dtype 버그, resume 로직 부재 등)와 두 차례의 크래시로 인한 진행분 손실.
- challenge 2: GLAD의 headline 성능(논문 Table 1)은 카테고리별 단일 모델(single-class) 기준이라, 우리가 필요한 multi-class(DiAD와 동일 조건) 설정에서는 논문 자체도 supplementary(Table S7)로만 다뤄 정보가 상대적으로 적음.
- challenge 2가 실제 문제인 evidence: `method4_glad/markdown/ECCV24_GLAD_Towards_Better_Reconstruction_with_Global_and_Local_Adaptive_Diffusion_Models_for_Unsupervised_Anomaly_Detection.md`의 4절(Table 1 vs Table S7 비교) — grid/transistor의 multi-class 개별 수치는 논문에 아예 보고돼 있지 않음.

### 1.4 원인 가설
- 현재 관찰한 limitation 또는 failure: PatchCore가 grid(패턴 반복성 위반)와 transistor(부품 배치 이상)에서 상대적으로 약함(`method1_patchcore/markdown/baseline_analysis.md`).
- 원인 가설 H3: PatchCore의 고정된 3×3 local aggregation은 global pattern-regularity 이상을 잡기에 불충분하다.
- 원인 가설 H4: PatchCore의 per-patch independent scoring은 spatial-arrangement 이상을 못 잡는다.
- 왜 H3/H4가 그럴듯한가: DiAD 재현에서 이미 grid/transistor가 다른 카테고리보다 유독 불안정한 추이를 보였음(`method3_diad/markdown/h3_h4_evaluation.md`) — 다만 이것이 "diffusion 재구성 계열 전체의 한계"인지 "DiAD 구현 자체의 한계"인지는 아직 구분이 안 됨. GLAD가 이 둘을 가르는 추가 데이터 포인트가 될 수 있음.
- H3/H4가 맞다면(그리고 GLAD의 적응형 메커니즘이 실제로 도움이 된다면) 관찰되어야 하는 현상: GLAD의 grid I-AUROC/transistor P-AUROC가 DiAD보다 안정적으로 높아야 함.

### 1.5 이번 주 선택한 방향
- 이번 주 해결 후보: GLAD(Yao et al., ECCV 2024) 재현 착수 — 피드백에서 언급된 4개 방법(GLAD/SimpleNet/Reverse Distillation/Dinomaly) 중 첫 착수 대상.
- 다른 후보보다 이것을 선택한 이유: GLAD는 애초에 DiAD의 대체 후보로 `related_work/`에서 먼저 읽었던 논문이라 재현 착수까지의 시간이 가장 짧았고, DiAD 재현 때 확립한 로컬 8GB GPU 세팅 패턴을 재사용할 수 있었음.
- 이 선택이 H3/H4를 어떻게 검증하는가: (다음 주 이후) GLAD로 grid/transistor category-wise 지표를 산출해 PatchCore·DiAD와 나란히 비교 예정. 이번 주는 그 비교가 가능한 재현 환경을 만드는 단계임.

### 1.6 이번 주 기여 또는 검토 초점
- 이번 주 brief가 보여주려는 핵심 판단: 아직 실험 결과는 없지만, GLAD 재현 환경을 실제로 동작하는 상태까지 구축했고(다수의 의존성/코드 버그 해결, resume 로직 추가로 재현성 확보), Windows Update로 인한 반복 크래시 원인을 진단해 근본적으로 해결했다는 것이 현재까지의 실질적 진척임.
- 이 판단을 지지하는 evidence 위치: `method4_glad/markdown/setup_notes.md`.

## 2. 사전 지식과 문제 정의

### 배경
- 이번 주 결과를 이해하기 위해 필요한 배경: W27(PatchCore 재현)에서 도출된 H3/H4, W28~W37(DiAD 재현)에서의 미결정 판단을 이어받는다.
- 이전 결과 또는 논문 맥락: PatchCore 평균 I-AUROC 99.1%(`method1_patchcore/markdown/baseline_analysis.md`), DiAD 재현 grid I-AUROC 0.588→0.764→0.654(개선 후 재하락), transistor P-AUROC 0.945→0.923→0.922(기준선 근처 정체) (`method3_diad/markdown/h3_h4_evaluation.md`).

### 기술 용어
- *I-AUROC* [1]: 이미지 한 장이 정상인지 불량인지를 판별하는 성능을 나타내는 지표이다. 0~1 사이의 값이며 높을수록 성능이 좋다. 예: grid의 점수는 0.654로, 다른 카테고리에 비해 이 판별을 잘 수행하지 못함을 의미한다.
- *P-AUROC* [1]: 불량이 있을 때 정확히 어느 픽셀이 불량인지 위치를 판별하는 성능을 나타내는 지표이다. 마찬가지로 0~1 사이의 값이며 높을수록 좋다. 예: transistor의 점수는 0.922이다.
- *ADS* [4]: GLAD가 사용하는 기능으로, 샘플마다 노이즈를 제거하는 단계 수를 자동으로 결정한다. 난이도가 낮은 샘플에는 적은 단계를, 난이도가 높은 샘플에는 많은 단계를 적용한다.
- *SAFF* [4]: GLAD가 사용하는 또 다른 기능으로, 정상 영역과 이상 영역을 구분해 정상 영역은 원본을 유지하고 이상 영역만 새로 복원한다.

### 표기법
| 표기법 | 설명 |
|---|---|
| `I-AUROC` | 이미지 전체의 정상/불량 판별 성능, 0~1 |
| `P-AUROC` | 불량 위치(픽셀) 판별 성능, 0~1 |

### 정의
정의 1 (H3 대상). grid와 같이 반복되는 무늬를 가진 제품에서, 개별 무늬는 정상처럼 보이지만 전체적으로는 규칙이 깨진 경우를 말한다.

정의 2 (H4 대상). transistor와 같이 여러 부품이 결합된 제품에서, 개별 부품은 정상이지만 배치·위치가 잘못된 경우를 말한다.

### 문제 정의
문제 1.
- 학습: 정상(불량이 아닌) 이미지만을 사용하며, grid·transistor 등 15개 제품 카테고리를 하나의 모델이 동시에 학습한다(카테고리별로 별도 모델을 두지 않음 — 다만 카테고리 이름 자체는 조건으로 제공할 수 있다).
- 테스트: 새로운 이미지가 주어지면 모델은 다음 두 가지를 판단해야 한다 — ① 해당 이미지가 정상인지 불량인지(I-AUROC로 평가), ② 불량이라면 어느 픽셀이 불량인지(P-AUROC로 평가).
- 목표: PatchCore가 특히 취약했던 grid·transistor 두 카테고리에서 PatchCore보다 높은 성능을 얻는 것이다.

## 3. 관련 연구

### 3.1 현재 문제를 푸는 큰 연구 흐름
- 큰 연구 흐름 1 — Memory-bank/feature 비교: PatchCore[1]가 대표. 핵심 아이디어는 사전학습 feature의 patch 단위 최근접 이웃 거리. 한계는 local aggregation 크기에 의한 global context 손실. 현재 문제와의 연결: H3/H4의 baseline.
- 큰 연구 흐름 2 — 전체 이미지 재구성(diffusion): DiAD[3], GLAD[4]가 대표. 핵심 아이디어는 diffusion denoising으로 정상 이미지를 재구성하고 원본과의 차이를 anomaly score로 사용. 한계는 GLAD 이전까지는 모든 샘플·영역에 동일한 절차를 적용해 이상 난이도 차이를 반영 못함(GLAD가 이 한계를 직접 겨냥). 현재 문제와의 연결: H3/H4의 직접적인 검증 대상.

### 3.2 현재 원인 가설에 대응하는 관련 연구
- 원인 가설 H3/H4와 관련된 prior work: GLAD[4]는 diffusion의 전역적 재구성 능력에 더해, 샘플별 adaptive denoising step(ADS)과 영역별 spatial-adaptive feature fusion(SAFF)을 추가로 제안.
  - H3/H4를 지지하거나 반박하는 근거: GLAD 논문 자체는 grid/transistor를 별도로 다루지 않아 직접적 근거는 아니지만, "고정된 절차가 이상 난이도 차이를 반영 못 한다"는 GLAD의 문제의식은 DiAD 재현에서 관찰한 grid의 비단조적 추이에 대한 원인 가설 후보를 제공(`method4_glad/markdown/ECCV24_GLAD_Towards_Better_Reconstruction_with_Global_and_Local_Adaptive_Diffusion_Models_for_Unsupervised_Anomaly_Detection.md` 5절).
  - 이 prior work가 제안하는 해결 방향: 샘플/영역 단위 적응적 처리.
  - 내 문제에 그대로 적용하기 어려운 이유: GLAD의 headline 성능은 single-class(카테고리별 모델) 기준이라, 우리가 필요한 multi-class 조건에서의 grid/transistor 개별 성능은 논문에 보고돼 있지 않음 — 직접 재현해서 확인해야 함.

### 3.3 이번 주 해결 후보 요약
- 후보(선택): GLAD[4].
  - 관련 연구 근거: 3.1/3.2 참고.
  - 왜 가능성이 있는가: DiAD와 같은 diffusion 재구성 계열이면서 "고정 절차" 한계를 명시적으로 다룸.
  - 왜 실패할 수 있는가: multi-class 설정에서의 GLAD 자체 성능이 논문에 충분히 보고돼 있지 않아, DiAD 대비 실제 개선 여부는 우리가 직접 재현해봐야 알 수 있음. 8GB GPU 제약으로 batch/스텝을 크게 축소해 논문 수준 학습에 못 미칠 가능성도 DiAD와 동일하게 존재.
  - 이번 주 판단: 선택(재현 착수, 결과는 다음 주).

## 4. 선택한 방법 또는 절차
- 이번 주 선택한 후보: GLAD(Yao et al., ECCV 2024) 재현 — 피드백에서 언급된 4개 방법(GLAD/SimpleNet/Reverse Distillation/Dinomaly) 중 첫 착수 대상.
- 다른 후보보다 이것을 선택한 이유: GLAD는 애초에 DiAD의 대체 후보로 먼저 읽었던 논문이라 재현 착수까지의 시간이 가장 짧았음. DiAD 재현 때 확립한 로컬 8GB GPU 세팅 패턴(8-bit Adam, batch 축소, step 단위 체크포인트)도 그대로 재사용할 수 있었음.
- 기존 연구와의 차이: 없음(공식 repo, https://github.com/hyao1/GLAD 재현). 구현 세부는 아래 protocol 변경 참고.
- 구현 또는 protocol 변경 (세부는 `method4_glad/markdown/setup_notes.md`):
  - `bitsandbytes` 0.37.2 → 0.49.2 (Windows 미지원 버전 대체)
  - 체크포인트 저장 경로를 OneDrive 동기화 폴더 밖(`C:/ai_local/glad_run`)으로 우회
  - MVTec-AD 데이터셋 루트의 stray 파일(`license.txt`/`readme.txt`) 제거
  - `imgaug` float32 dtype 거부 버그 패치(uint8 캐스팅)
  - `train_batch_size` 32→1, `gradient_accumulation_steps` 1→4 (effective batch 4, 8GB GPU 제약)
  - 공식 코드에 없던 체크포인트 resume 로직 추가(`accelerator.load_state`) — 크래시 시 처음부터 재시작되던 문제 해결
  - `dataloader_num_workers` 8→0 (Windows spawn multiprocessing 이슈, DiAD와 동일)
  - 안정성: Windows Update 자동 재부팅 정책 변경(`NoAutoRebootWithLoggedOnUsers`), `GladTrainingWatchdog` 예약 작업(15분 주기 자동 재시작), GPU 온도/배터리 감시 — DiAD 때 구축한 안전장치를 GLAD용으로 재구성
- 이 선택이 현재 원인 가설을 어떻게 검증하는가: (다음 주 이후) MVTec-AD multi-class 설정으로 category-wise I-AUROC/P-AUROC를 산출해 grid(H3)/transistor(H4)에서 PatchCore·DiAD와 비교 예정 — 이번 주는 그 비교가 가능한 환경을 만드는 단계였음.
